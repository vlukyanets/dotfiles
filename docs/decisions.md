# Decisions

Each row is a decision the owner made, with why. A changed decision is an
edited row.

| # | Decision | Why |
|---|---|---|
| 1 | A node is a one-to-one copy of a machine's files at their paths from `/`, in `nodes/<node>/` | The earlier feature engine was too heavy; a copy is read and changed like the machine itself |
| 2 | Owner and mode: `<user>:<user>` for `home/<user>/` and below, `root:root` elsewhere; a file 0644, or 0755 from git's executable bit; a directory 0755. `nodes/<node>/.meta` lists only the exceptions as `<mode> <owner>:<group> <path>`, a directory's path ending in a slash | Almost every file and directory has the defaults, so only the few others need writing down; git keeps the executable bit but nothing about directories |
| 3 | The scripts are a Python package, `dotfiles` in `dotfiles/`, with one `dotfiles` command and a subcommand for each job; it uses only the standard library | Python is easier to test than shell; one command keeps the jobs and their shared code together |
| 4 | Dependencies are kept in `pyproject.toml` and pinned in `uv.lock`; everything runs through `uv` | The same versions on every machine and in CI, from one command: `uv sync` |
| 5 | Tests run with pytest on a fake filesystem (pyfakefs), with fake owners | A test never touches the machine and does not depend on the user who runs it |
| 6 | `dotfiles add` refuses a file that looks like it holds a secret, by the rules in `secret_leaks.toml`, naming the line and the rule but never the value; `--force` copies it anyway, with a warning. It also warns about files closed to others | The repository is public: a pushed secret is leaked; refusing makes copying one a deliberate act |
| 7 | Secrets are checked by our own scanner, `dotfiles scan`, with the rules in `secret_leaks.toml`: hundreds of known token formats borrowed under MIT, with 28 regexes rewritten for Python, plus our own rules for what dotfiles hold, like `psk=` lines. The scanner weighs keywords, entropy and allowlists, and decodes base64, hex, percent and unicode-escaped text | It needs only Python and uv, so every machine and CI run the same full check; one rules file and one scanner cannot drift apart |
| 8 | The pre-commit hook in `.githooks/` runs `dotfiles scan --staged`; cloning does not turn it on. CI runs `dotfiles scan --history` on every pull request and on `master`, on `ubuntu-24.04`, with actions pinned by commit SHA and uv by version | The hook stops a secret before it is committed, since anything pushed to a public repository is leaked. CI, scanning every commit, is the backstop for a commit made without the hook, and pinning means a moved tag cannot change what it runs |
| 9 | CI runs the tests on every pull request and on `master`, on Python 3.12 on `ubuntu-24.04` | 3.12 is the oldest Python `pyproject.toml` allows, so a change that needs a newer one is caught before the merge |
| 10 | `dotfiles add` takes the node name explicitly | The hostname is not always the node's name, and a wrong guess puts files into the wrong node |
| 11 | `dotfiles install` replaces a file that differs, keeping the old one as a backup in the repository, in `.backups/<node>/<YYYYmmdd-HHMMSS>/`, which git ignores. The time is the run's start, so one run has one directory. A copy is the user's, 0600, and the old owner and mode go into that directory's `.meta` | Nothing on the machine is lost to an install; a backup beside the file could be read as one more config by a program that reads a whole directory, such as logrotate. A copy the user owns is read and removed without sudo |
| 12 | `dotfiles install` writes at once and has a `--dry-run`, like `add` | One habit for every command that changes something; the dry run shows what a run would do |
| 13 | `dotfiles install` changes an existing directory only when `.meta` has its line | A system directory such as `/etc` is never changed by accident |
| 14 | `dotfiles install`, `add` and `status` run as the user, and what the user cannot read or write goes through one sudo helper over pipes | The password is asked once, and the command itself never runs as root |
| 15 | `dotfiles cleanup` removes backups by whole runs: all of them, all but the last N of each node (`--keep N`), or those older than N days (`--older-than N`) | Backups are never removed by `install`, so `.backups/` would only grow |
| 16 | `dotfiles status` shows what on the machine differs from a node like `git status` does, the node as the index: it exits with 0 either way, `-v` adds a diff of each modified file, and it also lists directories off their defaults that have no `.meta` line | One familiar shape for the drift check; the diff shows what to change in the node, and the directories are what `install` leaves alone |
| 17 | A template is a node file ending in `.tmpl`, with `{{ name }}` placeholders, installed to its path without the suffix; its `.meta` line names the template | Only the files marked `.tmpl` are read for placeholders, so braces in any other file are safe, and which files are templates shows in their names |
| 18 | A template's values live outside the repository, in `~/.config/dotfiles/<node>.toml`, closed to others; `install` asks for a missing one without echo and adds it there, and `--dry-run` and `status` ask nothing | No value can reach the public repository by a git mistake; a new machine is filled by answering once |
| 19 | `dotfiles add --template` makes a template from a machine's file: each secret the rules find is named by the user, its value goes to the values file and its placeholder into the template; a value already there keeps its name | Making a template by hand is where a secret is forgotten; one name for one value keeps a password shared by two files in one place |
| 20 | `dotfiles status -v` diffs a template as it is against the machine's file with the template's known values put back as their placeholders | The diff shows which lines changed without showing the values; a value changed on the machine is unknown, so it still shows, and `-v` stays a command run only on purpose |
| 21 | CI also runs `ruff check`, with ruff's default rules, and `mypy` on `dotfiles/` and `tests/`, each a job of its own; both are pinned in `uv.lock` like the other development tools | Lint and type errors are caught before the merge; the defaults need no configuration to keep |
| 22 | uv's cache in CI is saved by one job, `cache.yml`, on a push to `master` or by hand; every other job only restores it | Jobs that save the same key at once race, and all but one fail to save; pull requests read the cache of `master` |
| 23 | `dotfiles restore <node> [<run>] [<path>…]` puts back a run of backups, the last one by default, or only the files named, the way `install` puts a node, keeping what it replaces in a new run | A run is laid out like a node, so restoring needs no code of its own, and a restore can be undone like an install |
| 24 | The command finds its repository in the checkout its code runs from, else in `$DOTFILES_REPO`, else in `~/.local/share/dotfiles`, where `dotfiles init [<url>]` clones it; it can be installed with `uv tool install git+https://github.com/vlukyanets/dotfiles` | A machine needs no clone made by hand, as with chezmoi, while `uv run` in a clone keeps working on that clone, the pre-commit hook included |
| 25 | `dotfiles init --slim` clones with `--filter=blob:none`; the old history is kept, never squashed | A machine downloads only the current files, while commit, push and pull work as usual; squashing would mean rewriting `master` and every clone, and pull request refs keep the old commits on GitHub anyway |
| 26 | `dotfiles forget <node> <path>…` removes files from a node with their `.meta` lines, and the directories left with no files with theirs; the machine keeps the files | A `.meta` line for a file the node no longer has stops `install`; git keeps no empty directory, so a line for one would stop it on the next clone |
| 27 | `nodes/<node>/.hooks` holds `<pattern> <command>` lines; after `install` or `restore` writes a file whose path matches, the command runs once, as the user by the shell, `sudo` written where needed; not with another `--root` | A changed config often needs a service to reread it; a plain file like `.meta` keeps it visible in one place, and running as the user gives the sudo helper no power to run commands |
| 28 | `nodes/<node>/.packages` lists a node's packages, a name per line; `add --package` adds installed ones, `forget --package` drops them, `install` installs the missing ones first, with paru, or pacman without it, on Arch and apt on Debian, chosen by `/etc/os-release`; packages not in the list are left alone and not listed | A node is one machine, so one list in its distribution's names needs no mapping between distributions; paru builds from the AUR as the user; cleaning packages up is the owner's, not the command's |
| 29 | `add`, `install`, `restore` and `status` refuse a machine that is not Arch, Debian or like them by `/etc/os-release`, whether or not the node lists packages; `init`, `scan`, `cleanup` and `forget` run anywhere | The owner's machines are Arch and Debian; elsewhere the paths, owners and packages a node holds were never meant for, and a clear refusal beats a half-right install |
| 30 | A node keeps a symlink as a symlink, its target as it is; its owner is the default of decision 2, set when it is made and never compared, and it has no mode and no `.meta` line. `install` replaces a symlink with another target, a file where the node has a symlink, or a symlink where it has a file, keeping the old one in the run | The enabled systemd units and `/etc/localtime` are symlinks; Linux ignores a symlink's mode and its owner matters only in sticky directories; a run keeps a symlink as a symlink, so `restore` puts it back with no code of its own |
| 31 | `dotfiles add <node>` with no path and no `--package` adds each file and symlink of the node that `status` lists as changed on the machine; it skips, naming each, a file missing on the machine and a template | Taking back a config edited in place is the usual step after a change on the machine; dropping a missing file is `forget`'s, and remaking a template from the machine's file could lose placeholders put in by hand |
